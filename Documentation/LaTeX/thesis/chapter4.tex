generated, independent of the caching bug. Both are stated here as real,
found-and-fixed defects, not hypothetical examples.

\section{ISCO-08 Knowledge Base Construction}
\label{sec:impl-kb}
% ------------------------------------------------------------

\textbf{Source:} ILO ISCO-08 Volumes~I and~II~\cite{ilo2012isco_v1,ilo2012isco_v2}.
\textbf{Coverage:} 436 unit groups (the exact official count), corrected via
a direct primary-source cross-check --- not 441 as an earlier internal
draft of this thesis stated, and not because of any ``ILO Geneva 2012
supplementary guidance'' (that explanation was investigated and found to
have no basis in any source checked; see Chapter~\ref{chap:architecture}).
\textbf{Embeddings:} \texttt{intfloat/multilingual-e5-small} in the
production-default profile; an additive \texttt{multilingual-e5-large}
profile exists and is measurably more accurate but is not yet the default.
%% VERIFY AGAINST CODE: specific HNSW parameters and payload field names
%% were not independently re-verified against backend/rag/ in this pass.

Real engineering finding from this construction work: the official
catalogue's \texttt{embedding\_text} for every entry was originally just
\texttt{"\{code\} \{2-4 word title\}"} (e.g.\ \texttt{"6122 Poultry
Producers"}), while the official ILO source workbook already on hand
carries full \texttt{Definition}, \texttt{Tasks include}, and \texttt{Included
occupations} columns for every entry --- silently discarded by the original
catalogue-normalisation script. Several thin-text codes acted as a
``magnet,'' matching 15--55$\times$ more often than their true frequency in
the evaluation set. This was fixed by building a real, opt-in enriched
catalogue text using the source workbook's actual definitions --- the single
largest accuracy improvement measured in this project (full results in
Chapter~\ref{chap:results}).

\section{Language Processing Implementation}
\label{sec:impl-lang}
% ------------------------------------------------------------

The \texttt{LanguageProcessor} handles six language codes:
\texttt{en}, \texttt{ar}, \texttt{ar-gulf}, \texttt{ur}, \texttt{hi},
\texttt{tl} (plus an \texttt{other} fallback). Gulf-dialect normalisation
uses a hand-built 79-rule dictionary, not an external library (see
Section~\ref{sec:impl-method}). NER extracts entities via a
\texttt{TaskType.GENERAL}-routed CrewAI agent (Ollama/Llama~3.2 primary,
with the real automatic fallback chain described in
Chapter~\ref{chap:architecture} if Ollama is unreachable) --- this degrades
to empty entities rather than a hard failure if the underlying LLM is down.
Language detection is confirmed to use \texttt{langdetect.detect\_langs()}
as its primary probabilistic detector, with a documented Devanagari
fast-path in the code specifically because ``langdetect sometimes misses
pure Hindi'' --- confirmed directly against the live source, matching (not
contradicting) the earlier draft's general framing here.

\section{Validation Agent}
\label{sec:impl-validation}
% ------------------------------------------------------------

The \texttt{ValidationAgent} enforces ten deterministic rules, confirmed
directly against \texttt{backend/agents/validation\_agent.py}:

\begin{itemize}
  \item \textbf{R01} Required fields (\texttt{employment\_status},
  \texttt{industry}) must be present and non-empty
  \item \textbf{R02} \texttt{hours\_per\_week} must be parseable as a number
  \item \textbf{R03} \texttt{hours\_per\_week} must be in $[1, 168]$
  \item \textbf{R04} \texttt{hours\_per\_week} $> 80$ triggers an outlier warning
  \item \textbf{R05} Unemployed respondent with a non-empty \texttt{job\_title}
  is a contradiction
  \item \textbf{R06} Unemployed respondent with \texttt{hours\_per\_week} $>0$
  is a contradiction
  \item \textbf{R07} Not-in-labour-force respondent with a non-empty
  \texttt{job\_title} is a contradiction
  \item \textbf{R08} Full-time employment with fewer than 20 hours/week
  triggers a warning
  \item \textbf{R09} Part-time employment with 35+ hours/week triggers a
  warning
  \item \textbf{R10} Employed respondent with 0 \texttt{hours\_per\_week} is
  an error
\end{itemize}

\textbf{This replaces the original draft's ten rules entirely}, which
described ILO ICLS-19-specific mechanisms (a wage gate, platform-worker
disclosure, national-employment-programme routing, an ``F3'' re-routing
rule to \texttt{not\_in\_labour\_force}) that do not exist as R01--R10 in the
real code. The real ten rules, listed above, are hours/employment-status
logical-consistency checks. An optional Stage-2 LLM semantic check exists
on top of these ten deterministic rules but was not independently
re-verified in detail in this pass.

\section{Testing}
\label{sec:impl-testing}
% ------------------------------------------------------------

The test suite spans \texttt{backend/tests/} and \texttt{eval/}, run via
\texttt{pytest backend/tests eval/ -q}. \textbf{Real, current count (this
project's most recent full run): 2,501 passed, 1 deselected}, not the ``18
mocked files'' an earlier internal draft of this thesis stated --- that
figure was stale even relative to this project's own mid-project state (44
files in \texttt{backend/tests/} alone at one verified point, growing
substantially further since). The one deselected test is a slow load test
(\texttt{@pytest.mark.slow}); no standing known failures. This count has
been independently reproduced multiple times, including nine consecutive
full runs under varying \texttt{PYTHONHASHSEED} values with byte-identical
results, confirming no hash-order non-determinism in the current suite.

A separate, pre-existing framework (\texttt{eval/legacy\_thesis\_ch6/
evaluate.py}, formerly \texttt{backend/evaluation/}) compares BM25, flat, and
hierarchical retrieval on a 100-item \emph{synthetic} corpus. This is real
and still used (its \texttt{BM25Baseline} class is imported by the main
evaluation harness), but --- stated precisely, unlike the original draft ---
its numbers are never the primary, citable evaluation result for this
thesis; the primary result comes from the real, external WISCO benchmark
(Chapter~\ref{chap:evaluation}).
