\chapter{Proposed System Architecture}
\label{chap:architecture}

The prototype combines a multilingual interview interface, deterministic
questionnaire control, retrieval-based classification, and human-review
support. This chapter distinguishes the survey API workflow from
alternative configurations evaluated offline.

\section{Design Principles}
\label{sec:arch-principles}

\begin{enumerate}[label=\textbf{P\arabic*.},leftmargin=*]
\item \textbf{Traceability.} Method labels, confidence scores, candidate
information, configuration identifiers, and logs support inspection.
Their correctness requires verification; their presence alone does not
establish reproducibility.
\item \textbf{Taxonomy alignment.} Classification references ISCO-08,
ISIC Rev.~4, ISCED~2011, and ISCED-F~2013
\cite{ilo2012isco_v1,unsd2008isic,unesco2012isced,unesco2015iscedf}.
Coverage and code-normalisation exceptions are reported separately.
\item \textbf{Privacy-aware design.} Authentication, respondent-session
ownership checks, audit records, and soft deletion are implemented.
Outstanding authorisation and data-lifecycle defects
(Chapter~\ref{chap:implementation}) prevent a claim of deployment readiness
or regulatory compliance.
\item \textbf{Explicit uncertainty.} Retrieval similarities and rule
scores support review decisions. They are heuristics, not empirically
calibrated probabilities of correct classification.
\item \textbf{Deterministic control.} Field order, clarification, skip
conditions, confirmation, and cross-answer validation are distinct from
classification and semantic-coherence checks.
\item \textbf{Modularity.} The live API invokes component modules directly,
without CrewAI hierarchical delegation. The repository also contains a
separate experimental hierarchical Crew, outside this default workflow.
\end{enumerate}

\section{High-Level System Architecture}
\label{sec:arch-overview}

\textbf{Interface layer.} Next.js provides login, interview, report, and
supervisor-review pages. Prompts target English, Arabic, Urdu, Hindi, and
Tagalog, with Gulf Arabic handled as an Arabic variety. Translated
interfaces and right-to-left presentation do not establish correct
language-specific answer handling. The Hindi/Urdu routing defect is
disclosed in Chapter~\ref{chap:implementation}.

\textbf{Application layer.} FastAPI authenticates requests, checks session
ownership, invokes components, persists answers, and assembles responses.
CrewAI constructs role-specific agents and tasks, while field routing,
catalogue lookup, and core coherence scoring are deterministic. Counting
agent-constructing modules does not measure agents executed per turn.

\textbf{Knowledge and persistence layer.} Qdrant collections are identified
by catalogue/embedding profile. PostgreSQL holds users, OTPs, sessions,
responses, audit/access/decision logs, quality reviews, HITL entries,
reports, and person-register records. Redis stores conversation state
with a 24-hour default time to live. An in-process context cache serves
active sessions, with best-effort Redis restoration after restart.
Database, cache, and Redis updates are not one atomic transaction.

\textbf{Model-access layer.} The LLM client exposes \texttt{GENERAL} and
\texttt{CRITICAL}. General tasks default to Ollama at temperature 0.3 and
may try configured Anthropic, Gemini, Groq, and OpenRouter providers.
Critical tasks select the configured Claude model at temperature 0.0
without provider fallback. Unpinned ISCO reranking requests
\texttt{GENERAL}; validation and quality-report components request
\texttt{CRITICAL}. Evaluation uses a strict model-selection function where
a model is explicitly pinned. Call-site configuration and execution
records determine which model ran. Successful end-to-end Claude inference
is not established by the archived experiments.

\section{Conversation Flow}
\label{sec:arch-fsm}

The five states are \texttt{GREETING}, \texttt{COLLECTING\_INFO},
\texttt{CLARIFYING}, \texttt{VALIDATING}, and \texttt{COMPLETING}.
A greeting advances to collection; failure to populate the requested
field enters clarification. Field order is recomputed when routing
answers change. Required-field presence leads to a summary for
confirmation or correction; confirmation advances to completion.

The branches contain 56 distinct implemented fields. A field is not
necessarily one question or one turn: clarification adds turns, prefill
can remove requests, and optional fields are not all completion
requirements. Demographic and feedback fields are shared across employed,
unemployed, and outside-labour-force paths. Employment-specific fields
cover occupation, duties, industry, hours, work arrangements, benefits,
and work quality. Conditional fields include field of study for higher
attainment, wage/contract items for paid employees, secondary-job hours,
active job-search methods, previous-employment details, platform-work
details, and an Emiratization item.

These rules adapt the project questionnaire; they do not demonstrate
full conformity with ILO labour-force measurement
\cite{ilo2013workstats}. Initial status is extracted from a respondent's
label, and the implemented unemployed-to-outside-labour-force reassignment
fires when both search and availability are negative. A field instrument
must establish reference-period work, temporary absence, availability,
search, and applicable exceptions through appropriate questions.

Rules R01--R10 check required fields, hours parseability/range/outliers,
employment-status contradictions, and full-time/part-time hour mismatches.
The wage gate and labour-force reassignment are conversation-control
rules rather than part of this validation set. The current API reports
validation findings but does not universally block confirmation when
data are invalid. Repeated clarification failure can accept an
unnormalised answer. Independent questionnaire and routing validation
therefore remain necessary.

\section{ISCO-08 Retrieval Pipelines}
\label{sec:arch-rag}

\textbf{Catalogue profiles.} The official-source catalogue contains
436 unit groups, 130 minor groups, 43 sub-major groups, and 10 major
groups. Armed Forces unit groups use internal padded forms
\texttt{0110}, \texttt{0210}, and \texttt{0310}; this is a code-normalisation
convention. Legacy and official profiles are distinct. The live API
constructs a bare \texttt{ISCOClassifier()}, whose default is
\texttt{legacy}, rather than the best-performing official enriched
E5-large configuration reported in Chapter~\ref{chap:results}.

\textbf{Hierarchical retrieval.} Search traverses major, sub-major, minor,
and unit levels using parent filtering and beam search. The legacy
hierarchical score combines stage similarities as
\begin{equation}
 c = 0.10s_1+0.20s_2+0.20s_3+0.50s_4.
\end{equation}
This is a heuristic confidence, not a calibrated probability.
Official-profile search settings are recorded in their evaluation
artifacts and summarised in Appendix~\ref{app:reproducibility}.

\textbf{Flat retrieval.} Direct search uses one unit-group collection;
ancestry can be reconstructed from the taxonomy. Official-text enrichment
adds definitions, tasks, and included occupations to embedding text.
E5-small uses 384-dimensional vectors and E5-large 1024-dimensional
vectors~\cite{wang2024multilinguale5}. Query and indexing configuration
must match the chosen profile.

\textbf{Reranking and review.} An optional LLM chooses among retrieved
candidates. A similarity score at least 0.92 permits bypassing reranking,
and confidence below 0.70 is a basic review trigger. Experimental
configurations can enable additional ambiguity policies. These thresholds
are not universal risk bounds. Legacy keyword/synonym handling differs
from official-definition enrichment. Collection creation does not specify
custom HNSW tuning parameters.

Chapter~\ref{chap:results} compares the recorded retrieval configurations.
Those offline results do not measure the default interview pipeline or
an unseen deployment population.

\section{ISIC Rev.~4 Industry Classifier}
\label{sec:arch-isic}

ISIC Rev.~4 organises economic activities into section, division, group,
and class levels~\cite{unsd2008isic}. The keyword table has 134 entries:
121 match official classes and 13 are non-standard. The enriched flat
index excludes the latter, covering 121 of 419 official classes. This is
partial coverage.

The default API uses the legacy keyword/LLM pipeline; hierarchical and
flat retrieval are alternative configurations. Examples include
6201 (Computer programming activities) and 4100 (Construction of
buildings). Successful examples do not establish population accuracy.
Occupation and employer industry are separate variables: an ICT
professional may work outside the ICT industry.

\section{ISCED Classifier}
\label{sec:arch-isced}

ISCED~2011 attainment (levels 0--8)~\cite{unesco2012isced} is distinct
from ISCED-F~2013 field of education~\cite{unesco2015iscedf}.
Attainment uses rules; field classification supports keyword and
retrieval configurations. Legacy combined confidence is
\begin{equation}
 c_{\mathrm{education}}=0.4c_{\mathrm{level}}+0.6c_{\mathrm{field}}.
\end{equation}
The score is an implementation heuristic. National qualifications and
ambiguous descriptions require independent mapping validation.

The field table contains 63 entries, of which 61 match official
definitions. The enriched flat index excludes the two non-standard
entries. Attainment accuracy cannot be inferred from field-classification
accuracy, and coverage must refer to the actual index evaluated.

\section{Semantic Relation Engine}
\label{sec:arch-sre}

The Semantic Relation Engine checks an ISCO occupation against an ISIC
section and an ISCED~2011 attainment level. Detailed ISCED-F field codes
are not inputs to its core score. Compatibility tables encode
project-authored occupational expectations; an official correspondence
source for these exact rules has not been established.

Let $q_I$ and $q_E$ represent industry and attainment compatibility.
The initial score is
\begin{equation}
 r=\begin{cases}
 0.55q_I+0.45q_E,&\text{both signals available},\\
 q_I,&\text{industry only},\\
 q_E,&\text{attainment only},\\
 0.80,&\text{neither available}.
 \end{cases}
\end{equation}
With $m$ moderate violations, the final score is
\begin{equation}
 S=\operatorname{round}_{4}
 \bigl(\min\{1,\max\{0,r+0.15m(1-r)\}\}\bigr).
\end{equation}
The coherent flag uses $S\geq0.70$. The missing-signal default of 0.80 is
an assumption, not observed evidence of compatibility.

Industry restrictions can produce HIGH violations. Attainment severity
depends on distance from an expected interval: one level is LOW, two
MODERATE, and more than two HIGH. Stricter minima are defined for
sub-major groups 22, 23, 25, and 26. These expectations can flag valid
non-traditional careers; they are not mandatory occupational entry
requirements.

The engine exposes a separate caller-confidence adjustment:
$+0.10$ at $S\geq0.90$, $+0.05$ at $S\geq0.70$, $-0.05$ at
$S\geq0.50$, and $-0.20$ otherwise. The live API scores
coherence and queues HIGH violations, but does not generally apply this
adjustment to returned/persisted ISCO confidence. An optional coordinator
can reconsider an uncertain occupation using cross-standard evidence.
These are distinct mechanisms, not one calibrated fusion model.

The rule-validation and endpoint tests in Chapter~\ref{chap:results}
check specified rules and queue creation. They do not establish
sensitivity, specificity, or fairness against independently adjudicated
respondent data.

\section{End-to-End Data Flow}
\label{sec:arch-dataflow}

A turn performs authenticated session lookup, context retrieval, language
processing when enabled, state update, relevant classifications, optional
coordination, coherence scoring, optional engagement analysis, validation
at the validation state, database commit, context persistence, and
logging. Completion persists collected fields and may trigger fallback
classification, person-register update, and quality review. Reports
aggregate stored responses and can run further enrichment/narrative
generation.

Call count and latency vary with state, input, fast mode, and model
configuration. Retrieval latency and end-to-end interview duration measure
different workloads. The review also found that refined classifications
or corrected titles can differ from stored responses. These defects limit
claims of complete end-to-end correctness until repaired and retested.
